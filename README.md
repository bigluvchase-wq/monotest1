# Моно для iPhone

Исходники тестовой версии. Проект открывается в Xcode из файла `Mono.xcodeproj`, схема `Mono`. Целевая система проекта — iOS 17 и новее. Тестовая сборка для App Store Connect использует актуальный Xcode из конфигурации Codemagic.

## Что внутри

- Интерфейс, анимации и логика опубликованной веб-версии 32 включены в пакет приложения. Их отображает WKWebView из локальных файлов. Для открытия экранов, работы с операциями и разбора введённого текста сайт не нужен.
- Голосовая кнопка использует системное распознавание iOS на русском. Когда iOS предоставляет распознавание на устройстве для русского языка, приложение выбирает его. В остальных случаях системному сервису может понадобиться сеть.
- В разделе «Настройки → Уведомления» можно включить напоминания iPhone. Моно планирует до 60 ближайших напоминаний и обновляет очередь после сохранения изменений и при возвращении в приложение. Сумма и название платежа входят в текст уведомления.
- Экспорт JSON и CSV открывает системное меню «Поделиться». Восстановление из JSON использует выбор файла. История внутри приложения хранится отдельно от Safari.
- Оплата, синхронизация через Telegram, отправка обращений, Face ID и виджеты требуют отдельной реализации. Состояние этих функций из веб-версии сохранено. Приглашение друга пока делится ссылкой на веб-версию.
- Пакет содержит проект и конфигурации сборки. Компиляция Xcode, подпись и проверка на физическом iPhone остаются шагами первой беты.

## Первый запуск на своём iPhone с Mac

1. Распакуй архив и открой `Mono.xcodeproj` в Xcode. В **Xcode → Settings → Accounts** добавь свой Apple Account.
2. Открой цель **Mono → Signing & Capabilities**, включи **Automatically manage signing**, выбери свою **Team**. Если `com.monomoney.ios` недоступен, задай уникальный идентификатор, например `com.<вашеимя>.monomoney`. Для последующих обновлений сохраняй тот же идентификатор и команду.
3. Подключи iPhone кабелем, разблокируй, подтверди доверие компьютеру. После сопряжения при необходимости включи **Настройки → Конфиденциальность и безопасность → Режим разработчика**, перезагрузи iPhone и подтверди включение.
4. Выбери свой iPhone рядом со схемой **Mono** и нажми **Run ▶**. Для личной проверки достаточно бесплатной **Personal Team**. Apple указывает, что её профиль установки действует 7 дней. После истечения запусти сборку через Xcode ещё раз.
5. Открой Моно, разреши микрофон и распознавание речи при запросе. После выдачи разрешений снова зажми кнопку, произнеси фразу, отпусти кнопку, проверь черновик и сохрани.

[Apple о Personal Team](https://developer.apple.com/help/account/basics/about-your-developer-account/) · [Apple о режиме разработчика](https://developer.apple.com/documentation/xcode/enabling-developer-mode-on-a-device)

## Windows и установка для Никиты и Жени через TestFlight

1. Создай закрытый репозиторий на GitHub. Распакуй архив и загрузи **содержимое** папки `Mono-iOS` в корень репозитория, включая `codemagic.yaml`, `Mono.xcodeproj`, `Mono` и по желанию `.github`. Участие в Apple Developer Program требуется для владельца команды, которая подписывает и загружает сборку.
2. В Apple Developer зарегистрируй уникальный **App ID**. В App Store Connect создай приложение и выбери его Bundle ID. Если используешь свой идентификатор, замени `com.monomoney.ios` в обоих файлах `Mono.xcodeproj/project.pbxproj` и `codemagic.yaml`.
3. В App Store Connect открой **Users and Access → Integrations → App Store Connect API**. Если доступ к API ещё не включён, владельцу команды нужно его запросить. Создай командный ключ для Codemagic. В **Codemagic → Team integrations** добавь интеграцию **Mono ASC** с Issuer ID, Key ID и файлом `.p8`. Приватный ключ загружай только в настройках интеграции.
4. В **Codemagic → Code signing identities → iOS** подготовь сертификат **Apple Distribution** и профиль **App Store** для выбранного Bundle ID. Codemagic может создать или получить эти материалы через интеграцию. При ручной загрузке сертификата понадобится и его приватный ключ.
5. Подключи репозиторий к Codemagic и запусти workflow **Моно · TestFlight**. Он применит профиль подписи, соберёт `.ipa` и загрузит его в App Store Connect. Для следующих загрузок нужен новый номер сборки. В шаблоне номер берётся из `BUILD_NUMBER` Codemagic.
6. Когда Apple обработает сборку, открой вкладку **TestFlight** в App Store Connect. Заполни сведения о бете и ответь на вопросы Apple по экспорту криптографии, если система их покажет. Внутреннее тестирование доступно участникам команды App Store Connect с подходящими правами. Для Жени без доступа к проекту создай внешнюю группу и отправь приглашение после проверки Apple.
7. На iPhone установи **TestFlight** из App Store, открой приглашение и нажми **Установить** напротив Моно. Бета устанавливается отдельной иконкой. Один билд доступен для тестирования до 90 дней. Следующие билды придут туда же.

[Codemagic: нативная сборка iOS](https://docs.codemagic.io/yaml-quick-start/building-a-native-ios-app/) · [Codemagic: подпись](https://docs.codemagic.io/yaml-code-signing/signing-ios/) · [Apple: TestFlight](https://developer.apple.com/help/app-store-connect/test-a-beta-version/testflight-overview/)

## Как перенести историю и проверить бету

1. В веб-Моно открой **Меню → Настройки → Ваша история — у вас → Резервная копия JSON**. Сохрани файл в «Файлы». Если экспортировал с компьютера, передай JSON на iPhone, например через iCloud Drive.
2. В установленном Моно открой тот же раздел, выбери **Восстановить из JSON** и укажи файл. Импорт заменяет историю внутри приложения целиком. Сравни баланс, последние операции и платежи.
3. Проверь голос на iPhone фразой «КБ триста, Самокат пятьсот». Должны появиться два расхода в категории «Продукты». Проверь «Вчера оплатил долями куртку за восемь тысяч». В черновике должны быть расход 2 000 ₽ за вчера и ещё три платежа по 2 000 ₽ с интервалом 14 дней.
4. В «Операциях» проверь дату над группой записей, раскрой расходы и сравни список. Проверь свайпы, тёмную тему, восстановление JSON и открытие приложения после завершения его работы. Создай пробный платёж и проверь уведомление при закрытом Моно.
5. Для следующей итерации пришли номер билда из TestFlight, модель iPhone, версию iOS, шаги, ожидаемый результат и скриншот. Для ошибки диктовки полезна исходная фраза и код из окна ошибки. На присланных скриншотах можно закрыть реальные суммы и названия.

Перед переходом на следующую сборку сохраняй JSON. Для данных в веб-версии и приложении синхронизация пока не предусмотрена.

## Проверки разработки

`node --test tests/*.test.cjs` проверяет протокол голосового моста, очередь напоминаний, подключение локальных ресурсов и пример с «Долями». Workflow `iOS build check` компилирует приложение для симулятора без подписи на GitHub Actions. Для проверки микрофона, уведомлений и импорта нужен реальный iPhone.
