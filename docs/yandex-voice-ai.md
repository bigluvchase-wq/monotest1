# Умный разбор фраз через Yandex Cloud

## Как работает

1. iOS распознаёт голос, как раньше. Аудиофайл на наш сервер не отправляется.
2. Пользователь включает «Настройки → Голос и приватность → Умный разбор» на этом устройстве. Согласие хранится отдельно от истории и не переносится синхронизацией на другие устройства.
3. Приложение отправляет распознанный или введённый текст на `POST https://api.monoapp.ru/api/voice/parse`. Прикладываются код привязки, ключ устройства в `X-Mono-Key` и небольшой контекст: местные дата и время, выбранный счёт, идентификаторы/названия/валюты счетов и целей, названия категорий. Балансы, история операций, аватар и ключ Яндекса не отправляются.
4. Сервер проверяет привязанный ключ, размер запроса и бюджет. Затем обращается к YandexGPT Pro 5.1 через Text Generation API с JSON Schema и отключённым логированием запросов у провайдера.
5. Сервер разрешает только финансовые записи и команды существующих форм. Общих ответов чата нет: ошибки и отказ от посторонней темы формируются по закрытому списку кодов. Названия, даты, суммы и идентификаторы проходят проверку.
6. Приложение показывает черновики или открывает формы для подтверждения. Данные не сохраняются автоматически. Удаление одной записи требует отдельного подтверждения с её названием; неоднозначные совпадения не удаляются. Массового удаления модель выполнять не может.
7. Если сервер выключен, недоступен, ответил ошибкой или исчерпан бюджет, приложение использует прежний разбор на устройстве и сообщает об этом. Редактирование фразы, закрытие формы или повторный разбор отменяют устаревший запрос.

Поддержаны расходы, доходы, переводы, пополнение целей, обычная оплата «Долями», создание напоминаний, обязательных платежей, целей, счетов, лимитов и вкладов, удаление одной записи. Для изменения существующей записи нужно выбрать её в интерфейсе; ИИ попросит уточнение. Финансовое здоровье и кредитная нагрузка ещё не вычисляются этой интеграцией. Модель не должна выдавать выдуманные оценки или общие советы.

## Что нужно в Yandex Cloud

- Каталог с активным платёжным аккаунтом и доступом к нужной модели.
- Сервисный аккаунт с ролью `ai.languageModels.user` в этом каталоге.
- API-ключ этого сервисного аккаунта с областью `yc.ai.languageModels.execute`.
- Node.js 20.20.2 или новее со встроенным `fetch` на сервере. Для этой интеграции обновление работающего Node.js 20.20.2 не требуется.

Используется явный URI `gpt://<folder_id>/yandexgpt-5.1`; другой совместимый URI можно задать в `YANDEX_MODEL_URI`. Нельзя произвольно подменять адрес провайдера из приложения. SpeechKit для этой цепочки не нужен: распознавание уже выполняет iOS.

Официальные инструкции: [API-ключ](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/get-api-key), [модели](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/generation/models), [Completion API](https://aistudio.yandex.ru/ru/docs/ai-studio/text-generation/api-ref/TextGeneration/completion), [отключение логирования](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/disable-logging).

## Обновление существующего сервера

Сначала сверить реальный `server.js`, путь процесса `mono-pay`, версию Node.js и конфигурацию nginx с репозиторием. Перед обновлением сделать резервную копию кода, `.env` и SQLite через `backup.js` (копирование одного `mono.db` при работающем WAL не гарантирует согласованность). Не заменять реальный `server.js`, если в нём есть отсутствующие в GitHub изменения.

На сервер должны попасть `server.js`, `voice-ai.js`, `voice-examples.js`, `voice-examples.json`, `voice-ai-check.js`. Файлы `voice-examples.js` и `voice-examples.json` обязательны для новой версии обработчика; переносить его отдельно нельзя. Новых зависимостей у рабочей интеграции нет. `package.json` добавляет только команду тестирования. Для `npm test` также скопировать `server/tests/` и выполнить `npm ci`.

В папке `/root/mono-server` добавить строки из [примера окружения](../server/.env.voice-ai.example) в **существующий** `.env`, сохранив настройки Робокассы, почты и базы:

```bash
cd /root/mono-server
nano .env
chmod 600 .env
node voice-ai-check.js
```

Не вставляйте секрет в команду shell, GitHub или чат. Редактируйте `.env` непосредственно на сервере. Пример `.env.voice-ai.example` содержит только заглушки.

Один тестовый запрос в Яндекс (платный, короткий, с вымышленным текстом):

```bash
node voice-ai-check.js --request
```

Если проверка успешна, установить `VOICE_AI_ENABLED=1` в `.env`, затем:

```bash
node --check server.js
node --check voice-ai.js
pm2 restart mono-pay --update-env
curl --fail --silent --show-error https://api.monoapp.ru/api/voice/status
```

Ожидается `{"enabled":true}`. Это подтверждает конфигурацию сервера; успешный вызов модели подтверждает отдельный `--request`. Если nginx маршрутизирует только отдельные старые `/api/`-адреса, добавить `/api/voice/` к тому же upstream без изменения оплаты и синхронизации. Выключение: `VOICE_AI_ENABLED=0` и перезапуск процесса; приложение продолжит локальный разбор.

Потребуется новая сборка приложения с `voice-ai.js` и включение переключателя «Умный разбор». До публикации также обновить страницу политики `site/privacy.html` и проверить сведения о данных в App Store Connect на соответствие фактическому сбору/хранению.

## Бюджет и хранение

- По умолчанию 50 попыток в сутки на зарегистрированный код и 500 на весь сервер. Суточные квоты используют UTC.
- Не больше 4 одновременных обращений к модели на процесс; тайм-аут Яндекса 12 секунд, приложения — 15 секунд.
- Один запрос: до 4000 символов фразы, тело до 64 КБ, до 3000 выходных токенов, максимум 30 финансовых записей и 5 команд.
- Попытка списывается перед обращением к Яндексу, включая ошибку провайдера: это сдерживает расходы при сбоях. Фактическая цена определяется тарифом модели, лимиты запросов не заменяют денежный бюджет в Yandex Cloud.
- Счётчики `voice_ai_usage` хранятся в SQLite, переживают перезапуск и очищаются спустя 7 дней. Фразы и ответы модели в базе не сохраняются и в логи приложения не печатаются. Nginx не должен писать тела запросов или заголовки авторизации в журнал.
- Эти ограничения защищают бюджет сервиса; массовую регистрацию устройств в публичном приложении дополнительно стоит защищать App Attest и наблюдением за расходами.

## Проверки

```bash
node --test tests/*.test.cjs
npm ci --prefix server
npm test --prefix server
```

Контрактные тесты проверяют суммы, даты, счета, валюты, исключение лишних данных и совместимость черновиков с финансовым движком. HTTP-тесты используют подменённый ответ Яндекса: проверяют авторизацию, размер запроса, формат вызова, обработку ошибок и квоты. Они не обращаются к платному API. Реальные качество разбора и задержку надо проверить на целевом каталоге и iPhone.

### Проверка настоящей модели с рабочим форматом

После базового `--request` и включения функции скопировать также `server/voice-ai-self-test.js` в папку сервера и выполнить:

```bash
cd /root/mono-server
node voice-ai-self-test.js
```

Это **два платных запроса**: два расхода из одной фразы и отказ на вопрос о скорости света. Проверяется тот же обработчик, JSON Schema и валидация, что в рабочем приложении, с отдельным портом на localhost и SQLite в памяти. Рабочая база не открывается, тестовые пользователи и финансовые операции не сохраняются. Проверка не заменяет проверку настоящей модели на пользовательских примерах и iPhone.

### Сложные фразы и правила разбора

`node voice-ai-self-test.js --complex` выполняет **6 платных запросов** к настоящей модели: смешанная фраза владельца с четырьмя операциями и напоминанием; зарплата и траты с разными датами; перевод между своими счетами, наличные и кешбэк; отрицание покупки; неясное поступление от друга; обмен валют без суммы зачисления. Тест проверяет число записей, суммы в копейках, категории, даты, счета, напоминание и запрос уточнения. Он не заменяет тест качества на большом наборе фраз.

В правилах Моно «питик» означает **500 ₽**. Это зафиксировано в инструкции модели, локальном разборе и тестах. Полученный долг записывается как поступление в категории «Займы»: остаток увеличивается, доход в итогах и прогнозах — нет. Отданный долг относится к расходам «Финансовые операции». Полноценный учёт остатков долгов по людям этой интеграцией не создаётся.

Даты относятся к своим действиям. Общая дата в начале блока действует вперёд до следующей даты; «заправился вчера» не переносит предыдущую покупку продуктов на вчера. Напоминание на завтра не создаёт сегодняшний расход. Неясное назначение поступления, сумма обмена или дата требуют уточнения, а не догадки.

Это настройка готовой модели инструкцией, ограниченным контекстом и проверкой ответа, а не дообучение её весов. Модель не запоминает исправления сама. Перед сменой модели или инструкции надо повторять набор проверок; рассматривать дообучение стоит после накопления проверенных примеров и анализа повторяющихся ошибок.

Если сложный пример отклонён с `invalid_ai_response`, выполнить `node voice-ai-self-test.js --complex --only-user --diagnose`: **один платный запрос** только для смешанной фразы. Диагностика печатает статус завершения, использование токенов и поля ответа модели на вымышленный тестовый текст, очищая секретный ключ из вывода. Она не используется в обработчике реальных пользовательских запросов и не включает логирование фраз в рабочем API.


### Библиотека примеров из проекта

`server/voice-examples.json` содержит 64 синтетических/проектных примера: 28 длинных фраз (85 операций) из тестов, 24 команды из подсказок приложения и 12 новых фраз. У каждого есть источник и назначение:

- `prompt` — 19 проверенных образцов для инструкции модели;
- `evaluation` — 35 контрольных фраз, которые никогда не подставляются в инструкцию как примеры;
- `review` — 10 фраз со спорными эталонами: неполная сумма, пришедший, но ещё не оплаченный штраф, свой брокерский счёт и другие случаи. Они сохранены для разбора и не используются как правильные ответы.

Вместо передачи всех 64 фраз `voice-examples.js` выбирает до 3 подходящих по признакам текущего запроса. Бюджет самих примеров — 6000 символов. Даты разрешаются относительно контекста устройства, ссылки на счета и цели берутся только из переданного справочника. Примеры с отсутствующими категориями, целями или несовместимой валютой пропускаются. Это примеры в инструкции готовой модели, а не дообучение весов и не чтение истории пользователя.

Для контрольной проверки:

```bash
node voice-ai-self-test.js --corpus --limit=8 --diagnose
```

Команда выше делает **8 платных запросов**. `--limit=35` проверяет все 35 контрольных фраз и делает 35 запросов. Сначала нужно устранить ошибки формата на одиночной диагностике `--complex --only-user --diagnose`, затем запускать большой набор. База остаётся в памяти, настройки и рабочие операции не меняются. CLI сохраняет `voice-ai-report.json` рядом с тестовым скриптом: это отчёт по вымышленным фразам, без ключей. Автоматически сравниваются действия, суммы, даты, счета и категории; названия и тексты команд требуют просмотра отчёта.


### Пустые элементы ответа модели

В настоящем ответе YandexGPT на смешанную фразу наблюдались четыре корректные по суммам/датам записи, одно заполненное напоминание и дополнительный объект напоминания со всеми 17 полями в `data`, равными `null`. Такой точный пустой шаблон схемы теперь удаляется перед проверкой команд: в нём нет параметров действия. Объекты неизвестного типа, неполные шаблоны, пустые строки вместо null и команды с хотя бы одним заполненным неверным полем продолжают отклоняться. Финансовые записи не удаляются и их суммы/категории не исправляются автоматически. Неверная категория «Покупки» для продуктов уточнена в инструкции и должна быть повторно проверена на модели.

## Согласование сложных списков

Для финансовых списков из трёх и более записей сервер также запускает существующий парсер приложения. Его результат используется только при полном разборе без ошибок, совпадении количества и каждой суммы по порядку и успешной обычной серверной валидации. Это согласует категории, даты и направление переводов другим людям с приложением. Суммы автоматически не исправляются. Команды, долги, отрицания, обмен валют, рассрочки и ответы с уточнениями исключены. Это проверка всей цепочки, а не оценка качества одной модели.

В автономный каталог сервера вместе с `voice-ai.js`, `voice-examples.js`, `voice-examples.json` и `voice-ai-self-test.js` необходимо скопировать файлы `engine.js`, `schedule.js`, `speech-dates.js`, `speech-categories.js` из `Mono/Web` той же версии. В checkout репозитория используются исходные файлы `Mono/Web`.
