# Совместный счёт «Вместе»

Это отдельное пространство учёта на двух пользователей. При принятии приглашения оно создаётся пустым: личные операции, счета, цели, вклады, лимиты и напоминания не копируются. Личная история продолжает храниться под прежним ключом `mono-v2` и синхронизироваться прежним способом; общая история имеет отдельные таблицы сервера и отдельный кэш телефона. При запуске приложение открывает личное пространство.

## Использование

Меню → Счета → Добавить счёт → Совместный счёт → ID партнёра из шести цифр. На главном экране второго телефона автоматически открывается отдельное окно с ID приглашающего и кнопками «Согласиться / Отказаться». Оно не перебивает уже открытые окна или диктовку. До подтверждения доступ к данным не возникает. Приглашение действует семь дней; отправитель может создать до пяти приглашений за сутки. Сам ID не даёт доступа: сервер проверяет привязанный секрет устройства каждого участника.

На главной список «Счёт для записи» содержит личные и совместные счета. Выбор переключает всё пространство учёта, включая баланс, доходы, расходы и операции. В операциях одна кнопка текущего режима «Личный» или «Вместе» находится под балансом. В меню переключателя нет; внутри счетов, целей, лимитов, платежей, категорий, вкладов и напоминаний он расположен справа от добавления. Статистика и все финансовые разделы используют выбранное пространство. Перед созданием цели, обязательного платежа, вклада или напоминания режим выбирается кнопкой в самом разделе. Лимиты создаются в выбранном пространстве. Голосовой ввод использует текущее пространство. Можно добавить дополнительные счета внутри общего пространства.

Удаление основного совместного счёта открывает выход из пары. Личные данные остаются; у партнёра общая история сохраняется. Когда выходит последний участник, сервер удаляет оставшееся общее пространство. Чтобы образовать новую пару, оставшийся участник сначала выходит из прежней.

## Синхронизация

Общий снимок хранится на существующем сервере в Москве. Изменения отправляются через 700 мс после записи; проверка обновлений выполняется примерно раз в 12 секунд при открытом приложении, а также при возвращении в приложение и восстановлении сети. Дополнительная подписка для совместного пространства не требуется.

Сервер принимает запись только от участника и только с актуальной ревизией. При параллельных изменениях выполняется трёхстороннее объединение: независимые записи сохраняются обе. Если одну запись изменили или удалили одновременно, приложение предлагает выбрать вариант для конфликтующих полей. Несвязанные изменения сохраняются при любом выборе. Некорректное объединение не записывается.

В открытом общем пространстве изменения без сети сохраняются отдельно на телефоне. Перед переходом в личное приложение пытается отправить их; если это не удалось, они останутся в общем кэше до следующего открытия «Вместе» с сетью. Полноценный холодный запуск общего пространства без сети не предусмотрен: сначала проверяется членство. Для выхода из пары требуется синхронизировать ожидающие изменения.

Тема, профиль и настройки уведомлений остаются локальными настройками пользователя. В общий серверный снимок не включаются профиль, аватар и обращения в поддержку. Общие правила категорий и настройки финансового здоровья относятся к общему пространству.

Уже загруженные личные и общие напоминания планируются на телефоне вместе, с учётом существующего ограничения очереди в 60 уведомлений. Новые общие напоминания партнёра загружаются при открытом приложении. Серверных push-уведомлений для фоновой доставки новых приглашений и напоминаний в этой версии нет.

## Обновление сервера

Перед установкой приложения требуется обновить сервер. Скрипт `server/deploy-together.sh FULL_COMMIT_SHA` запускается пользователем на VPS: сохраняет прежние файлы, вызывает существующий согласованный SQLite-бэкап, скачивает файлы строго указанного коммита, проверяет синтаксис и перезапускает `mono-pay`. Новые таблицы создаются автоматически, личная таблица пользователей не переносится и не очищается. Новые зависимости и изменение `.env` не нужны; Яндекс остаётся отключён.

Восстановление файлов: скопировать сохранённые файлы из выведенного каталога резервной копии обратно в `/root/mono-server` и перезапустить `pm2 restart mono-pay --update-env`. Восстановление SQLite из бэкапа удалит более поздние записи — выполнять только при необходимости, остановив процесс.

## Проверки

`node --test tests/*.test.cjs` и `cd server && npm test`. Серверные проверки включают настоящую авторизацию по ключам, подтверждение только получателем, отсутствие копирования личной истории, запрет доступа постороннему, контроль ревизии и сохранность данных партнёра после выхода. Дополнительно проверен сценарий двух отдельных Chromium-сессий с сервером и SQLite: приглашение, пустой общий счёт, независимые личные истории, обмен и параллельное добавление операций, выход из пары. Проверка нативной сборки и двух реальных iPhone требует Codemagic/Xcode и развёрнутого сервера.

Браузерный регрессионный сценарий: `node tools/verify-shared-ui.cjs` (требуется Playwright; путь к модулю можно передать в `MONO_PLAYWRIGHT_MODULE`, путь к Chromium — в `MONO_CHROMIUM_PATH`). Он сам запускает временные HTTP-серверы, использует SQLite в памяти и два раздельных браузерных контекста; производственные данные не меняет. Проверяет автоматическое приглашение, выбор счёта, обновление главной/операций, все семь панелей разделов, повторную отрисовку и выравнивание кнопок, обычное меню и отсутствие вертикального скролла главной. Снимки сохраняются во временный каталог. Ограничение одной пары проверяется на сервере для отправителя и получателя. Эти правки интерфейса не требуют повторного обновления VPS.
